# 代码智能审查Agent - 项目设计文档

## 1. 项目概述

### 1.1 项目背景

在日常开发、代码提交、版本迭代、CodeReview流程中，传统代码审查完全依赖人工完成，存在大量行业痛点：人工审查效率低下、容易遗漏潜在漏洞、代码规范不统一、性能问题难以提前发现、新人代码质量无法把控、审查标准因人而异。

现有工具如IDE插件、静态代码检测工具仅能完成**固定规则的语法校验、格式校验**，无法做到语义级代码分析、业务逻辑漏洞排查、性能隐患识别、代码可读性评估以及针对性优化建议输出，对于逻辑BUG、冗余代码、不合理设计、SQL隐患等深层次问题无能为力。

基于以上痛点，本项目实现**Java原生代码智能审查AI Agent**，无重型AI框架依赖，纯后端工程化实现，完成「代码接收 → 语法规范校验 → 语义智能审查 → RAG知识增强 → 漏洞检测 → 性能分析 → 代码优化 → 结构化报告生成」的全自动化闭环，替代传统人工CodeReview，实现代码审查标准化、智能化、自动化。

### 1.2 项目定位

面向研发团队的**AI代码智能审查、自动化CodeReview实战项目**，贴合企业研发流程、代码提测、版本上线、日常开发质检真实场景。

区别于传统静态代码检测工具，本项目核心是 **AI Agent语义级智能审查 + 工程规则双重校验 + RAG知识库增强**：

- 突破传统工具固定规则限制，大模型深度理解代码语义与业务逻辑
- RAG知识库注入企业内部编码规范、历史BUG案例、最佳实践，使审查结果贴合企业实际
- AI自动识别隐性BUG、性能隐患、不规范写法、设计缺陷
- 纯Java后端架构，校验规则可控、审查逻辑可扩展、适配企业代码规范

### 1.3 核心目标

- 实现代码全自动智能审查，替代人工CodeReview，提升研发质检效率
- 覆盖语法规范、代码格式、安全漏洞、性能隐患、逻辑缺陷多维度审查
- RAG知识库检索增强，注入企业规范与历史案例，提升审查准确性与适配性
- 自动定位问题代码行、输出问题描述、风险等级、错误原因
- 智能生成优化方案、重构代码、规范化写法，实现代码自动修复参考
- 支持批量代码审查、历史审查记录溯源、统计代码质量数据
- 知识库自学习：历史审查结果回流沉淀，持续提升审查能力
- 生成标准化审查报告，为代码提测、上线、团队质检提供依据

## 2. 需求分析

### 2.1 功能需求

#### 2.1.1 代码上传与解析能力

- 支持单段代码文本粘贴、多文件代码批量上传审查
- 自动识别代码类型，默认适配Java代码，可扩展Python、Go、JS等主流语言
- 代码预处理：空行过滤、注释清洗、代码片段规整、格式统一

#### 2.1.2 多维度智能审查能力

- **代码规范审查**：命名不规范、缩进混乱、注释缺失、格式不统一、魔法值未定义、冗余导入
- **语法与BUG审查**：语法错误、空指针风险、参数未校验、数组越界、逻辑死循环、异常捕获不规范
- **性能隐患审查**：循环嵌套查询、未关闭流、频繁创建对象、集合初始化缺陷、SQL慢查询隐患、无效循环遍历
- **安全漏洞审查**：SQL注入风险、敏感信息硬编码、权限判断缺失、接口参数未脱敏
- **代码设计审查**：代码冗余、重复逻辑、耦合度高、方法过长、职责不单一、可维护性差

#### 2.1.3 RAG知识库检索增强

- 接入企业内部编码规范文档，实现规范条文与审查结果关联
- 沉淀历史BUG案例库，审查时检索相似代码模式，预警同类问题
- 维护最佳实践代码片段库，为优化建议提供企业级参考实现
- 支持知识库文档上传、分块、向量化、索引、检索的全链路管理
- 审查结果可回流至知识库，形成「审查 → 学习 → 提升」的正向循环

#### 2.1.4 AI智能优化能力

- 针对所有问题代码，精准定位代码行数与问题位置
- 自动分析问题根因、风险影响范围、出现场景
- 结合RAG知识库检索结果，输出符合企业规范的最佳优化方案
- 输出优化思路、重构方案、规范化代码片段
- 支持新旧代码对比展示，直观查看优化效果

#### 2.1.5 审查报告生成能力

- 自动生成结构化审查报告，包含总体评分、问题汇总、风险分级
- 附注RAG知识库匹配的规范条文引用，增强报告说服力
- 分类统计规范问题、BUG隐患、性能问题、安全漏洞数量
- 输出整体代码质量评估、团队编码问题总结、优化建议

#### 2.1.6 历史记录与复盘能力

- 持久化每次审查记录、问题明细、优化结果
- 支持历史审查记录查询、对比、溯源复盘
- 统计个人/团队代码质量趋势、高频问题TOP排行

### 2.2 非功能需求

- **稳定性**：支持大段代码、批量代码审查，任务不堆积、不丢失
- **可用性**：大模型调用超时、解析异常具备兜底策略，正常返回基础规则审查结果；RAG检索失败时降级为纯LLM审查
- **可扩展性**：可新增审查规则、新增代码语言、新增审查维度、自定义企业规范、扩展知识库类型
- **安全性**：上传代码仅本地处理，不上传第三方服务器，保障企业代码隐私安全；知识库文档本地向量化存储
- **高性能**：代码审查任务异步处理，线程池隔离，不阻塞前端请求；向量检索支持近似近邻搜索加速

## 3. 整体架构设计

### 3.1 架构思想

采用**Java后端分层工程化 + Agent经典闭环架构 + RAG检索增强**，遵循「代码接收 → 规则校验 → RAG知识检索 → AI语义审查 → 问题聚合 → 优化生成 → 报告输出」的Agent执行链路。全程后端主控，AI仅负责语义分析与智能优化，基础规则校验、数据持久化、任务调度、风险判定全部由Java工程掌控，RAG知识库作为中间增强层为AI审查注入企业专属上下文，兼顾智能化与企业安全性、可控性。

### 3.2 五层整体架构

#### 1）接入层（Controller）

接收前端代码提交、审查查询、报告导出、历史记录查询、知识库管理请求，完成参数校验、代码预处理、权限校验，调度Agent核心服务，返回标准化审查结果与AI优化内容。

#### 2）Agent调度核心层（核心）

系统中枢模块，负责代码审查全流程调度：接收代码 → 基础规则校验 → RAG知识检索 → AI语义深度审查 → 问题聚合去重 → 智能优化生成 → 报告组装 → 结果持久化，串联完整审查闭环。

#### 3）RAG知识增强层（新增）

审查链路的核心增强模块，位于基础规则校验与AI语义审查之间，为AI审查提供企业专属知识上下文：

- **文档管理模块**：知识文档上传、解析、分块管理
- **向量化模块**：Embedding模型调用、文本向量化、批量处理
- **向量存储模块**：向量索引构建、近似近邻搜索、向量持久化
- **检索路由模块**：多路召回策略、相似度排序、结果融合去重
- **知识回流模块**：审查结果自动标注、高质量案例回流入库

#### 4）工具能力层

封装所有可被AI调度的后端审查工具，实现能力可插拔、规则可配置：

- 代码预处理工具（清洗、格式化、分片）
- 基础规则校验工具（规范、语法、格式校验）
- AI语义审查工具（BUG、性能、安全、设计缺陷分析）
- 代码智能优化与重构工具
- 审查报告生成与数据统计工具
- RAG检索工具（向量检索、关键词检索、混合检索）

#### 5）基础服务层

包含LLM大模型客户端、Embedding模型客户端、向量数据库连接、异步线程池、数据库持久化、日志记录、异常捕获、任务重试、数据统计等基础能力。

### 3.3 核心业务流程（Agent完整闭环）

1. **代码接入预处理**：接收用户提交的代码片段，自动清洗无效空行、冗余注释，格式化代码，完成基础合法性校验

2. **基础规则审查**：后端执行固定工程规则校验，筛查格式、命名、语法、基础规范问题

3. **RAG知识检索增强**（新增核心步骤）：
    - 3a. 对提交代码进行语义向量化
    - 3b. 在向量知识库中检索相似代码模式、相关规范条文、历史BUG案例
    - 3c. 进行关键词+向量混合检索，融合多路召回结果
    - 3d. 按相似度排序，提取Top-K相关知识点作为AI审查上下文

4. **AI语义深度审查**：Agent调用大模型，结合RAG检索的企业规范与历史案例上下文，基于代码语义与业务逻辑，深度识别隐性BUG、性能隐患、安全漏洞、设计缺陷

5. **问题聚合去重**：合并基础规则与AI审查结果，去除重复问题，划分风险等级（高/中/低），附注RAG匹配的规范来源

6. **AI智能优化与RAG规范对齐**：针对每一条问题，AI结合RAG知识库中的企业最佳实践，自动生成优化思路、修复方案、可直接替换的重构代码

7. **报告组装输出**：聚合所有问题、优化方案、代码评分、规范引用，生成标准化审查报告

8. **数据持久化与知识回流**：保存审查记录、问题明细、优化结果；高质量审查案例经审核后回流入RAG知识库

### 3.4 RAG知识库在审查链路中的定位

```
                    ┌──────────────────────────┐
                    │     RAG 知识增强层        │
                    │  ┌────────────────────┐   │
 代码输入 ──────────┤  │  向量检索  │ 关键词检索│   │
                    │  │  混合召回  │ 结果排序  │   │
                    │  └────────────────────┘   │
                    │  ┌────────────────────┐   │
                    │  │ 企业规范 │ 历史案例  │   │
                    │  │ 最佳实践 │ 缺陷模式  │   │
                    │  └────────────────────┘   │
                    └──────────────────────────┘
                              ↓ 知识上下文
 基础规则审查 ──→ AI语义深度审查 ──→ 问题聚合 ──→ 优化生成 ──→ 报告输出
```

## 4. 核心模块详细设计

### 4.1 代码预处理模块

对上传的原始代码进行标准化处理，统一审查入口，保证审查准确性：

- 清洗无效空行、多余空格、冗余注释，避免干扰AI识别
- 代码格式化、代码片段分片，适配大模型单次输入长度限制
- 非法代码、恶意代码、超长代码拦截校验

### 4.2 基础规则校验模块

纯后端硬规则实现，无需依赖大模型，高效筛查常规代码问题，保证审查兜底能力：

- 编码规范校验：类名、方法名、变量名命名规范，常量定义规范
- 代码格式校验：缩进、空行、括号格式、代码整洁度
- 基础语法校验：关键字错误、语法缺失、结构不完整
- 通用开发规范：魔法值、未使用变量、冗余导入、空方法

### 4.3 LLM智能语义审查模块

项目核心智能能力，通过结构化Prompt约束大模型输出标准化JSON结果，实现语义级深度审查，区别于传统静态检测工具。审查时注入RAG检索的企业规范与历史案例作为上下文：

- **逻辑BUG审查**：识别空指针风险、参数校验缺失、死循环、逻辑漏洞、异常处理不当
- **性能隐患审查**：识别循环查库、IO流未关闭、对象频繁创建、集合使用不当、低效遍历
- **安全漏洞审查**：识别硬编码密钥、SQL注入风险、权限缺失、敏感信息泄露
- **代码设计审查**：识别代码冗余、耦合过高、方法臃肿、违背单一职责、可扩展性差

### 4.4 代码智能优化模块

针对所有审查出的问题，自动生成落地优化方案，实现「查出问题 + 给出修复代码」一站式能力。优化方案结合RAG知识库中的企业最佳实践，确保修复代码符合团队规范：

- 精准定位问题代码行、问题类型、风险等级
- 详细说明问题产生原因、潜在影响、优化必要性
- 输出优化思路、重构方案、规范化可运行代码
- 附注优化建议引用的企业规范条文或历史案例来源
- 支持新旧代码对比展示，方便开发者快速替换修复

### 4.5 审查报告与统计模块

聚合所有审查数据，生成可视化、标准化审查结果，替代人工总结：

- 代码质量综合评分（0-100分）
- 高、中、低风险问题分类统计
- 各类问题占比、代码缺陷分布汇总
- RAG知识库匹配的规范条文引用列表
- 整体代码质量评估、团队编码规范整改建议

### 4.6 异步任务调度模块

基于自定义线程池实现代码审查任务异步处理，避免大代码片段审查阻塞主流程：

- 大代码分片异步审查，提升审查效率
- 任务超时熔断、异常重试、失败兜底
- 任务执行状态实时记录，支持进度查询

## 5. RAG知识库详细设计

### 5.1 RAG知识库整体架构

RAG（Retrieval-Augmented Generation）知识库作为审查链路的中间增强层，在AI执行语义审查之前，从向量知识库中检索与企业规范、历史案例相关的高质量知识片段，注入LLM Prompt上下文，使AI审查从「通用代码审查」升级为「贴合企业实际规范的专属审查」。


### 5.2 知识来源与分类

RAG知识库汇聚四大类企业研发知识，形成多维度代码审查知识体系：

| 知识类型 | 内容说明 | 应用场景 | 更新频率 |
|---------|---------|---------|---------|
| **编码规范文档** | 企业Java编码规范、命名约定、注释规范、分层架构规范、异常处理规范、日志规范等 | 审查时匹配规范条文，判断代码是否符合企业标准 | 规范变更时更新 |
| **历史BUG案例库** | 已修复的历史缺陷代码、根因分析、修复方案、影响范围 | 相似代码模式预警，避免同类问题重复出现 | 每次重大BUG修复后沉淀 |
| **最佳实践代码库** | 团队评审通过的高质量代码片段、推荐实现模式、性能优化范例 | 为AI优化建议提供企业实际落地参考 | 定期评审入库 |
| **缺陷模式库** | 常见代码坏味道特征、反模式、安全漏洞模式、性能陷阱 | 增强AI对隐性问题的识别准确率 | 持续积累 |

### 5.3 文档处理与向量化流程

```
  原始文档
     ↓
  ┌─────────────────┐
  │ 1. 文档解析      │  支持 Markdown、PDF、纯文本、代码文件
  │    格式识别与提取  │  去除格式标记、提取纯文本内容
  └────────┬────────┘
           ↓
  ┌─────────────────┐
  │ 2. 文本清洗      │  去除无关字符、统一换行、处理特殊符号
  │    标准化预处理    │  代码块与自然语言段落分离处理
  └────────┬────────┘
           ↓
  ┌─────────────────┐
  │ 3. 智能分块      │  基于语义边界切分（非固定字数截断）
  │    Chunking      │  代码块按函数/类边界切分，文档按段落/章节切分
  │                  │  Chunk大小：200-800 tokens，overlap：50-100 tokens
  └────────┬────────┘
           ↓
  ┌─────────────────┐
  │ 4. 元数据标注    │  标注：文档来源、知识类型、适用语言、创建时间
  │    上下文标记      │  标注：关联规范ID、关联BUG编号、标签
  └────────┬────────┘
           ↓
  ┌─────────────────┐
  │ 5. 向量化        │  调用 Embedding 模型生成向量
  │    Embedding     │  推荐模型：BGE-large-zh / text2vec-large-chinese
  │                  │  向量维度：1024（以实际模型为准）
  └────────┬────────┘
           ↓
  ┌─────────────────┐
  │ 6. 向量存储      │  写入向量数据库，构建索引
  │    索引构建       │  同时存储原始文本 + 元数据便于回溯
  └─────────────────┘
```

### 5.4 向量数据库选型

优先选择与Java生态集成良好、支持本地部署的方案：

| 方案 | 优势 | 劣势 | 推荐场景 |
|------|------|------|---------|
| **Milvus**（推荐） | 高性能向量检索、支持混合搜索、分布式扩展、Java SDK成熟 | 部署运维成本稍高 | 企业级生产环境 |
| **Elasticsearch + dense_vector** | 与现有ES技术栈统一、支持全文+向量混合检索 | 向量检索性能不如专用向量库 | 已有ES技术栈 |
| **Pgvector**（轻量推荐） | PostgreSQL原生扩展、零额外运维、与业务库统一 | 大规模向量检索性能有限 | 中小规模、快速启动 |
| **Chroma** | 轻量级、易上手 | Java SDK不成熟 | 原型验证阶段 |

**推荐方案**：项目初期选用 Pgvector 实现零额外运维的快速启动，大规模场景迁移至 Milvus。

### 5.5 检索策略设计

#### 多路召回 + 精排策略

```
  用户提交代码
       ↓
  ┌────────────────────────────────────────┐
  │           多路召回（粗排）                │
  │                                        │
  │  ① 向量语义召回         ② 关键词召回      │
  │  · 代码 → Embedding      · 提取关键标识符  │
  │  · 近似近邻搜索(Top-20)   · BM25全文匹配   │
  │  · 返回语义相似片段       · 返回关键词片段   │
  │                                        │
  │  ③ 标签过滤召回         ④ 规范精确匹配     │
  │  · 按代码类型过滤        · 规范ID/标题匹配  │
  │  · 按知识类型过滤        · 直接关联引用     │
  └───────────┬────────────────────────────┘
              ↓
  ┌────────────────────────────────────────┐
  │           结果融合去重                    │
  │  · 相同chunk多路命中 → 合并            │
  │  · 来源权重加权（规范 > 案例 > 实践）     │
  └───────────┬────────────────────────────┘
              ↓
  ┌────────────────────────────────────────┐
  │           精排（Rerank）                  │
  │  · 交叉编码器模型重排序                  │
  │  · 或LLM直接评估相关性（小模型）          │
  │  · 输出 Top-K（K=5~10）最佳匹配          │
  └───────────┬────────────────────────────┘
              ↓
         注入LLM Prompt
```

#### 检索参数配置

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 向量召回数量 | Top-20 | 粗排阶段向量检索返回数量 |
| 关键词召回数量 | Top-10 | BM25关键词检索返回数量 |
| 最终注入数量 | Top-5 | 精排后注入Prompt的知识片段数 |
| 相似度阈值 | 0.65 | 低于此阈值的片段丢弃 |
| 多路融合权重 | 向量:0.5 / 关键词:0.3 / 标签:0.2 | 融合排序权重 |

### 5.8 知识回流与自学习机制

RAG知识库不仅是静态知识源，更具备自学习进化能力：

```
  审查任务完成
       ↓
  ┌──────────────────────────────┐
  │  高质量案例自动识别           │
  │  · 评分 > 80分的审查结果     │
  │  · 人工确认的高价值问题发现   │
  │  · 新类型BUG首次发现          │
  └──────────┬───────────────────┘
             ↓
  ┌──────────────────────────────┐
  │  案例自动结构化               │
  │  · 提取问题代码 + 修复代码   │
  │  · 标注问题类型、风险等级     │
  │  · 关联规范条文              │
  │  · 生成案例摘要              │
  └──────────┬───────────────────┘
             ↓
  ┌──────────────────────────────┐
  │  人工审核（关键环节）          │
  │  · 技术负责人Review          │
  │  · 确认案例质量与通用性       │
  │  · 去隐私处理（脱敏）         │
  └──────────┬───────────────────┘
             ↓
  ┌──────────────────────────────┐
  │  回流入库                     │
  │  · 向量化入库                │
  │  · 更新索引                  │
  │  · 标记为「已验证案例」       │
  └──────────────────────────────┘
```

**自学习闭环效果**：随着审查任务不断执行，高质量案例持续沉淀，知识库从启动时的「企业规范 + 初始案例」逐步进化为「企业规范 + 海量实战案例」，审查准确率与适配性持续提升。

## 7. 核心接口设计

### 7.1 代码审查接口

- **提交代码智能审查**：`POST /agent/code/review/submit`
- **查询审查任务列表**：`GET /agent/code/review/task/list`
- **查询审查详情与优化代码**：`GET /agent/code/review/detail/{taskId}`
- **获取审查报告**：`GET /agent/code/review/report/{taskId}`
- **新增/编辑审查规则**：`POST /agent/code/review/rule/save`
- **代码质量数据统计**：`GET /agent/code/review/stat`

### 7.2 RAG知识库管理接口

- **上传知识文档**：`POST /agent/rag/doc/upload`
    - 支持 multipart/form-data 上传，自动触发文档解析 → 分块 → 向量化流程
- **查询知识文档列表**：`GET /agent/rag/doc/list`
    - 支持按知识类型、适用语言、状态筛选，分页返回
- **获取文档分块详情**：`GET /agent/rag/doc/chunks/{docId}`
    - 返回文档所有分块内容、向量化状态、命中统计
- **删除知识文档**：`DELETE /agent/rag/doc/{docId}`
    - 级联删除关联分块及向量索引
- **重建向量索引**：`POST /agent/rag/doc/{docId}/reindex`
    - Embedding模型切换后，重新分块并重建向量
- **检索知识测试**：`POST /agent/rag/search/test`
    - 输入查询文本，返回Top-K匹配知识片段及相似度得分，用于调优检索参数
- **知识质量反馈**：`POST /agent/rag/feedback`
    - 对检索结果进行点赞/点踩，驱动检索策略优化
- **知识回流提交**：`POST /agent/rag/feedback/submit`
    - 将高质量审查案例提交至知识库审核流程

- **问题可定位、可修复、可溯源**：精准定位代码行、输出风险分析、提供可直接替换的修复代码，同时引用企业规范条文佐证，真正落地提效

- **代码隐私安全可控**：全程本地处理，支持Embedding模型本地部署，向量库本地存储，自主掌控审查逻辑与数据，无第三方工具隐私泄露风险，适配企业内网部署
